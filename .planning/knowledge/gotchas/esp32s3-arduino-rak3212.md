# Gotchas — ESP32-S3 (RAK3212 / RAK3112) under Arduino core 2.0.16 + TFT_eSPI + RadioLib

Recorded 2026-09-24 during the RAK3212 port (Phase 0). Each item says what it was checked against.

| # | Gotcha | Evidence | Consequence in this repo |
|---|---|---|---|
| 1 | The ESP32-S3 Arduino variant default **SDA is GPIO8 = SX1262 NRESET** inside the RAK3112 module; default SCL 9, SS 10, MOSI 11, MISO 13, SCK 12. | `framework-arduinoespressif32@3.20016.0/variants/esp32s3/pins_arduino.h:26-32` | Never call `Wire.begin()` or `SPI.begin()` pin-less. `touch.cpp` passes pins; `lora_link.cpp` calls `SPI.begin(5,3,6,-1)` before `radio.begin()`. Rule written into `board_rak3212.h` and `docs/PIN_MAP.md`. |
| 2 | `SPIClass::begin()` is a **no-op once the bus is begun**, and RadioLib's Arduino HAL calls `spi->begin()` **without pins**. | `libraries/SPI/src/SPI.cpp:71-74`; RadioLib 7.7.1 `src/hal/Arduino/ArduinoHal.cpp:98-100` | The pin-ful `SPI.begin()` must run first or FSPI attaches to GPIO10-13 (the LCD bus). |
| 3 | TFT_eSPI 2.5.43 on the S3 **crashes on the first write unless `USE_HSPI_PORT=1`** (its default FSPI raw-register mapping points at the flash SPI). With the flag it instantiates its own `SPIClass(HSPI)` = SPI3, leaving the global `SPI` (= FSPI/SPI2 on S3) free. | bench-proven in `my-Claude-buddy/firmware/platformio.ini` (2026-05-03); `TFT_eSPI/Processors/TFT_eSPI_ESP32_S3.c:15`; `SPI.cpp:350` | Display on SPI3, SX1262 on global `SPI`; no bus sharing, no lock needed between the loop core and the LoRa task. |
| 4 | LEDC channel→timer is `(chan/2)%4`: channel 1 shares timer 0 with the buzzer (channel 0). | `cores/esp32/esp32-hal-ledc.c:64` | A PWM backlight must use channel 2 (timer 1) or `ledcWriteTone()` on the buzzer retunes it. Backlight currently digital via `TFT_BL=42`. |
| 5 | HWCDC (USB-Serial-JTAG) TX **blocks up to 100 ms per write** when no host drains it; RX is a 64-byte HW FIFO drained by ISR into a 256-byte queue. | `cores/esp32/HWCDC.cpp` | `Serial.setTxTimeoutMs(5)` in `setup()`; console rule: one command per write, <= 96 chars, wait for the prompt. |
| 6 | `getLocalTime()` defaults to a **5 s blocking wait** while unsynced. | `cores/esp32/esp32-hal-time.c:83` | `ntpGetEpoch()` uses `time(nullptr)` (non-blocking). Pre-existing calls in `ntpGetIsoTimestamp()/ntpGetTimeStr()` still block when NTP never synced — open item R11 in the plan. |
| 7 | An asserted DTR/RTS from a serial monitor **holds the S3 in reset** on native USB. | PlatformIO docs / bench practice | `monitor_dtr = 0`, `monitor_rts = 0` in the `rak3212` env. |
| 8 | PlatformIO builds **every `lib_deps` entry** for an env, used or not — the `native` env inherited TFT_eSPI from `[env]` and failed on `Arduino.h`. | `pio test -e native` output, 2026-09-24 | `[env:native]` overrides `lib_deps = throwtheswitch/Unity@^2.6.1`. |
| 9 | Renaming a source file (`rfid_reader.cpp` → `rfid_mfrc522.cpp`) changed the esp32dev image bytes with **identical** RAM/Flash sizes: link order moved code around. The only compile-time timestamp in the image (`12:36:24`) belongs to Espressif's precompiled IDF libraries, not to our build, so it is not the cause. | `cmp`/`strings` on the two Phase-0 images, 2026-09-24 | Compare RAM/Flash sizes for the "unchanged board" gate, not image hashes. Gate result: RAM 52120 B / Flash 1082433 B identical, 0 src warnings. |
| 10 | RadioLib join/uplink calls **block** (`activateOTAA()` ~6-7 s incl. JOIN_ACCEPT windows; `sendReceive()` ~2.4-3.3 s across RX1/RX2). | RadioLib 7.7.1 LoRaWAN sources (sibling vendored copy) | All radio work lives on a FreeRTOS task on core 0; loop() talks through a queue. |
