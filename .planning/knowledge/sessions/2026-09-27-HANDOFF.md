```bash
#    the station parks in RECONNECTING, LoRa still joins)

sleep 3   # the CDC port re-enumerates after esptool's reset; an immediate open fails with "Device not configured"
tools/bench/serial_capture.py --reset --seconds 45 --send "lora show" --send "lora hb" --after 34
```

Gate lines: `[LoRa] SX1262 up (AS923, TCXO 1.8V, DIO2 RF switch)` → `[LoRa] OTAA DevEUI=3CDC75FFFE6F85DC …`
→ `[LoRa] JOINED AS923 (new session); uplink DR3 (SF9)` within ~10 s → `lora hb` →
`[LoRa] uplink OK fPort=11 len=20 fcnt=… rx=0` → ChirpStack device Events: join + `up` with
`object.type = "heartbeat"`, `offline_reason = "BOOT_NO_WIFI"` (no WiFi creds) or `"none"`.
Then reboot (`--reset` capture): `[LoRa] session restored (no re-join)` and fcnt continues.
Then `lora clear-session yes` → a fresh join. `lora show` → task stack high-water > 1.5 KB free.

Failure signatures: `radio.begin failed (-2)` = SPI order/pins; join `-1116`/`-6` = keys/region/
gateway; `-5 TX_TIMEOUT` = DR not pinned; "uplink OK" + server `No device-session exists` =
stale session (`lora clear-session yes`).

## NeoPixel — deferred; resume from here, do not re-derive

PROVEN on 2026-09-24 (bring-up sketch `pix` console, captures in the CLAUDE.md state block):
- `neopixelWrite()` routes RMT signal 81 (`RMT_SIG_OUT0`) to GPIO17, output enable 1, idle LOW;
  with `pix inv on` the pad idles HIGH — so the GPIO matrix, the RMT channel and the pad all work.
- `pix pad`: drive HIGH reads 1, drive LOW reads 0 → no short, the pad toggles.
- A private RMT channel (`pix rmt`) and a cycle-counted bit-bang driver (`pix bang`) run too.
- Header J5-9 = GPIO17 (RAK3212 datasheet, WebFetch — second-hand); wiring is on the pixel's
  +5V/Din/GND input row (Arif's photo), C1 fitted.
- Dark with VDD 5 V and with VDD 3.3 V (Arif). GPIO17 is the S3 IOMUX `U1TXD` but UART1 never
  claims it (`RFID_UART_TX -1`; core 2.0.16 `esp32-hal-uart.c:153`).

UNKNOWN (never measured): the waveform/amplitude at the pixel's Din pad, the voltage at its +5V
pad under load, the pixel family (WS2812B-V5 needs VDD ≥ 3.5 V and data ≥ 0.7·VDD).

Resume checklist (any one settles it): Saleae on the pixel Din ("Addressable LEDs (Async)"
analyzer; expect a 24-bit frame every 333 ms, 3.3 V swing) · DMM on the pixel +5V pad · a diode
in the 5 V feed (≈ 4.3 V VDD, threshold ≈ 3.0 V) · NPN inverter (1 k base from GPIO17, 1 k
pull-up to 5 V on Din) + `pix inv on` · a known-good pixel on the same wires.
Note for later: the core's fixed 0.4/0.8 µs timing has T0H at the V5 datasheet maximum; if a V5
pixel misreads zeros (bright white) the app needs its own RMT driver with T0H 0.3 µs.

## Tooling to remember

- Flash: `scripts/flash.sh rak3212` (never `pio run -t upload` on this board). Wait ~3 s before
  opening the port after a flash.
- Serial: `tools/bench/serial_capture.py` only (opening the port any other way resets the S3).
- App console: `help`, `sys info` (POST results), `lora show|join|hb|clear-session yes`,
  `rfid raw on`, `rfid baud <n>`, `ui qc`, `ui touch on`.
- Bring-up console: `ping`, `pix status|pad|gpio|core|rmt|bang|pin <n>|rgb r g b|inv on|off|off`.
- Knowledge MCP: `rmg-rfid-station-knowledge` on the gateway (`get_handoff` returns the newest
  `*HANDOFF*.md` = this file); resync with `tools/sync-knowledge-mcp.sh` after doc changes.
- esp32dev regression guard: `pio run -e esp32dev` (52160 B RAM / 1084497 B flash on 2026-09-24).
